## 为什么是这几个模块（面向业界求职的设计说明）

博士求职（尤其 AI Infra / 大模型系统方向）与纯学术求职看的材料不同：**招聘方关心「你能不能把系统跑得更快」**，
所以页面在「论文」之外补了四类证据。这也是本次改版新增内容的依据：

| 模块 | 对应招聘方的问题 | 建议写法 |
| --- | --- | --- |
| **实习经历** | 你在真实集群上动过手吗？ | 团队 → 负责模块 → 技术方案 → **量化收益**（吞吐↑/P99↓/显存↓/成本↓）→ 产出（上线 / 合入主干 / 专利） |
| **开源贡献** | 你的代码别人敢用吗？ | 仓库 + PR 编号 + 一句话影响；合入 main 的 PR 比"参与过某项目"有力得多 |
| **性能基准档案** | 数据能复现吗？ | 硬件配置 + baseline + 对比数据 + 复现脚本，一页表格胜过十句形容词 |
| **技术博客 / 分享** | 你能把系统问题讲清楚吗？ | 源码分析、调优笔记、组会与会议 talk；面试常直接拿博客内容追问 |
| 求职意向（Open to） | 你到底想做什么岗位、什么时候来？ | 明确岗位方向、实习时间、毕业与校招届别、城市，方便 HR 与内推人一句话转发 |
| **简历 PDF** | 能发给面试官吗？ | 导出为 `assets/resume.pdf`，一页为宜；页面同时保留 `Ctrl+P` 的打印样式 |
| 技术栈关键词 | JD 里的关键词命中了吗？ | PyTorch / Megatron-LM / DeepSpeed / FSDP / vLLM / Triton / NCCL / RDMA / Slurm / ncu 等 |

> 补充建议（未做进页面，视情况再加）：
> Google Scholar 主页链接、论文 PDF 下载、中英文双语版（外企/海外岗位）、
> 系统竞赛（ASC / PAC / 昇腾挑战赛 / MLSys 类比赛）、推荐人（References，通常单独提供给 HR）。

## 已实现的特性

- 响应式布局：桌面 / 平板 / 手机三档断点（新增中等宽度下导航自动收窄），移动端为抽屉式导航
- 深色模式：右上角一键切换，首次访问跟随系统，选择写入 `localStorage`
- 滚动动效：区块进入视口渐显，技能条按比例展开
- 导航高亮：滚动时自动高亮当前区块
- 无障碍：跳转链接、`aria` 属性、可见焦点环
- 尊重 `prefers-reduced-motion`：系统开启「减少动态效果」时自动关掉动画
- 打印样式：`Ctrl+P` 可直接输出为简洁的浅色文档

## 后续可自行修改的地方

1. **头像**：`index.html` 中 `.avatar` 目前是 `WZJ` 文字占位。把 `<span>WZJ</span>` 换成
   `<img src="assets/avatar.jpg" alt="王子杰" />`，并在 `style.css` 的 `.avatar` 里加
   `overflow: hidden;` 与 `img { width: 100%; height: 100%; object-fit: cover; }` 即可。
2. **技能条进度**：`style.css` 中搜索 `--w:`，按需调整百分比（纯展示用）。
3. **项目链接**：若项目已开源，可在对应 `<article class="project">` 内加一个
   `<a class="btn btn--ghost" href="...">查看仓库</a>`。
4. **更新内容**：直接编辑 `index.html` 里的文字即可，无需重新构建。
5. **导航项**：如需增删导航，改 `#navLinks` 里的 `<a href="#锚点">`，并保证锚点与 `<section id="...">` 一致；
   导航项增多时注意 `style.css` 第 16 节里的响应式断点。
